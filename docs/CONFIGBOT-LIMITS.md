# ConfigBot — چیزهایی که هست، و چیزهایی که نیست

این سند عمداً زود نوشته شده. بهتر است قبل از اینکه پول و زمان بگذاری بدانی
کجا دیوار است تا اینکه بعد از دپلوی بفهمی.

---

## ۱. سرور VPN روی کلودفلر نمی‌آید — و این قابل دور زدن نیست

این مهم‌ترین جمله‌ی این سند است.

**Cloudflare Workers فقط HTTP/HTTPS دارد.** یک ورکر نمی‌تواند سوکت TCP یا UDP
باز کند. VLESS، Trojan، WireGuard، Hysteria2 — همه‌شان روی TCP/UDP خام کار
می‌کنند. پس:

| چیز | روی کلودفلر؟ |
|---|---|
| ربات تلگرام | ✅ |
| مینی‌اپ | ✅ |
| پنل ادمین | ✅ |
| دیتابیس (D1) | ✅ |
| تولید کانفیگ | ✅ |
| لینک اشتراک | ✅ |
| پرداخت و بررسی فیش | ✅ |
| هوش مصنوعی (Workers AI) | ✅ |
| **سرور VPN** | ❌ **به VPS نیاز دارد** |

این همان محدودیتی است که Minecraft Bedrock روی Spectrum ندارد — یک دیوار
معماری، نه یک تنظیم که فراموش شده باشد.

**راه‌حل واقعی:** یک VPS ارزان (Hetzner، Contabo، یا هر ارائه‌دهنده‌ای که
پول ریال/کریپتو قبول کند) + **Marzban** رویش. کد این پروژه یک
`MarzbanDriver` کامل دارد که با API خود Marzban حرف می‌زند. تو فقط آدرس پنل
و نام کاربری/رمز ادمین را در پنل ادمین وارد می‌کنی.

**چیزی که اینجا نیست و وانمود هم نشده:** هیچ «پروکسی رایگان نامحدود» یا
«endpoint مجانی VLESS» در این پروژه وجود ندارد. آن‌ها یا از کار افتاده‌اند یا
مال شخص دیگری‌اند و فروختنشان دزدی است.

### `MockNodeDriver` چیست و نیست

یک درایور درون‌حافظه‌ای است که اجازه می‌دهد **کل** زنجیره — سفارش، پرداخت،
صدور کانفیگ، چرخش، اشتراک — بدون VPS تست شود.

- در پنل ادمین با برچسب `mock` نشان داده می‌شود.
- کانفیگ‌هایش به هیچ کلاینت واقعی نمی‌رسند، چون سروری پشتشان نیست.
- جای VPS را نمی‌گیرد و تظاهر به گرفتنش نمی‌کند.

اگر نودی در دیتابیس `panel_url` نداشته باشد، به‌جای اینکه کل بوت بخوابد،
mock می‌گیرد. این یک تصمیم آگاهانه است: یک نود بدپیکربندی نباید کل ربات را
از کار بیندازد.

## ۲. پرداخت — ساده‌ترین راه واقعاً ساده است

تو گفتی با زرین‌پال کار نکردی. پس ترتیب این است:

### کارت‌به‌کارت (پیش‌فرض، بدون هیچ ثبت‌نامی)

روز اول کار می‌کند. تنها چیزی که لازم است:

1. در پنل ادمین → تنظیمات، شماره کارت + نام + بانک را وارد کن.
2. تمام. دکمه‌ی «کارت به کارت» برای کاربر ظاهر می‌شود.

**تا وقتی این سه فیلد خالی است، دکمه اصلاً نشان داده نمی‌شود.** یک دکمه که
۵۰۰ می‌دهد بدتر از نبودنش است.

جریان: کاربر سفارش می‌سازد → کد پیگیری می‌گیرد → واریز می‌کند → عکس فیش را
در ربات می‌فرستد → یک لایه‌ی غربالگری بررسی می‌کند → اگر همه‌چیز دقیق بود
خودکار تأیید می‌شود، وگرنه در صف پنل ادمین می‌نشیند.

**قاعده‌ی سخت:** کد رهگیری تکراری = رد قطعی. کد رهگیری تنها چیزی است که
می‌شود با بانک چک کرد؛ اگر قبلاً استفاده شده، پول دوباره نیامده.

### درگاه‌های آنلاین

`ZarinpalGateway` و `NextpayGateway` کامل نوشته و در برابر API مستندشان
پیاده‌سازی شده‌اند. ولی:

- `available()` تا وقتی کلید نداده‌ای `false` برمی‌گرداند.
- پس در UI نشان داده نمی‌شوند.
- حالت sandbox برچسب «تستی» دارد و هرگز به‌جای پول واقعی جا زده نمی‌شود.

## ۳. هوش مصنوعی — چه چیزی را واقعاً می‌چرخاند

**لایه‌ی ۱: قواعد قطعی (آفلاین، رایگان).** بیست و چند جمله‌ای که کاربران هر
روز می‌گویند — «کانفیگم کار نمیکنه»، «قیمت پلن سه ماهه»، «موجودیم چقدره».
بدون توکن، بدون تأخیر، بدون وابستگی به یک سرویس بیرونی.

**لایه‌ی ۲: Workers AI.** فقط برای چیزهایی که قاعده نمی‌تواند: خواندن رسید،
نوشتن جواب پشتیبانی، خلاصه‌سازی تیکت.

**اگر مدل خاموش باشد، ربات خاموش نمی‌شود.** لایه‌ی ۱ جواب می‌دهد.

### قاعده‌ای که با سیستم نوع تضمین شده، نه با انضباط

مدل فقط می‌تواند **نام یک ابزار** را برگرداند. هر عددی که به مشتری گفته
می‌شود — مبلغ، حجم، تاریخ انقضا، موجودی — از D1 خوانده می‌شود و توسط ما
رندر می‌شود. مدل هیچ‌وقت عدد نمی‌گوید.

این یعنی یک مدل که هذیان می‌گوید نمی‌تواند به کسی بگوید «اشتراکت ۳ روز دیگر
تمام می‌شود» وقتی تمام نشده.

### ابزارهایی که مدل اجازه دارد صدا بزند

فقط این‌ها. یک نام ابداعی اجرا نمی‌شود — تستش هم نوشته شده.

`get_my_subscriptions`, `get_order_status`, `list_plans`, `start_purchase`,
`rotate_config`, `get_wallet`, `create_ticket`, `get_node_status`

### Prompt injection

تلاش برای «دستور قبلی را نادیده بگیر»، گرفتن prompt سیستم، یا SQL probing:
شناسایی می‌شود، در `audit_log` ثبت می‌شود، و اجرا نمی‌شود. ربات یک خط
مؤدبانه می‌گوید و تمام.

## ۴. ضدنشتی — واترمارک

هر کانفیگی که صادر می‌شود یک شناسه‌ی ۸ کاراکتری hex در remark دارد:

```
vless://…#⭐ هلند · Reality · 4f2a91c0
```

اگر کانفیگ تو در یک کانال تلگرامی پیدا شد، در پنل ادمین → «پیگیری نشتی»
همان URI را بچسبان و بفهم مال کیست. بعد یک دکمه: «چرخش فوری».

**چرخش لینک را عوض نمی‌کند.** فقط کلیدها عوض می‌شوند. پس کاربر مجبور نیست
دوباره import کند، و کانفیگ لو رفته از همان لحظه از کار می‌افتد.

### یک باگ واقعی که همین‌جا پیدا شد

واترمارک اول با `urlToken()` ساخته می‌شد که base64url است (شامل حروف بزرگ،
`-` و `_`). ولی همه‌ی جستجوها hex کوچک انتظار داشتند. یعنی واترمارکی که
اصلاً قابل پیدا کردن نبود — بدتر از نداشتنش، چون وانمود می‌کرد قابل ردیابی
است.

باگ دوم: URI را قبل از decode با regex می‌گشتم. جداکننده‌ی `%20` قبل از
واترمارک یک `0` دارد که خودش hex معتبر است، پس مقدار استخراج‌شده یک کاراکتر
بلندتر از مقدار ذخیره‌شده بود و هیچ‌وقت مچ نمی‌شد.

## ۵. چیزی که هنوز تست نشده — `TESTED = NO`

صادقانه:

- **دپلوی واقعی روی Cloudflare** — در این محیط هیچ هاست کلودفلری قابل دسترسی
  نیست (همه HTTP `000`). `wrangler deploy` اینجا اجرا نشده.
- **import در کلاینت واقعی** — پنج فرمت اشتراک تست round-trip دارند، ولی هیچ
  v2rayNG یا Hiddify واقعی به آن‌ها داده نشده.
- **Marzban واقعی** — `MarzbanDriver` در برابر API مستند نوشته شده، ولی به یک
  پنل زنده وصل نشده.
- **درگاه واقعی** — زرین‌پال/نکست‌پی با fetch جعلی تست شده‌اند، نه با سرور
  واقعی آن‌ها.
- **تلگرام واقعی** — موتور مکالمه با یک transport جعلی تست شده. `getMe`,
  `setWebhook` و `initData` واقعی اجرا نشده‌اند.
- **UI در مرورگر واقعی** — HTML تولید می‌شود و `node --check` روی JS‌اش پاس
  می‌شود، ولی در مرورگر باز نشده.
- **سایت در مرورگر واقعی** — ۳۰ تست هندلر واقعی `fetch` را صدا می‌زنند و مسیر،
  CSP، کوکی امضاشده و سقف سفارش را تأیید می‌کنند، ولی هیچ‌کدام در مرورگر رندر
  نشده‌اند. جریان کپی‌کردن لینک و آپلود فیش فقط در سطح HTTP تست شده.
- **دانلود کلاینت‌ها** — نام assetها از GitHub API گرفته و هر URL با HEAD چک
  شده (`302` به CDN)، ولی خودِ فایل‌ها هرگز دانلود و نصب نشده‌اند. از این
  سندباکس هاست CDN گیت‌هاب `http=000` است.
- **آپلود فیش در R2** — مسیر کد نوشته شده، ولی هیچ R2 واقعی تست نشده.

هر چیزی که تست شده، تستش در `configbot/test/` است و با
`npx vitest run configbot/` اجرا می‌شود.

## ۵٫۵. سایت — و چرا فایل exe/apk اختصاصی نداریم

سایت روی سه مسیر سرو می‌شود: `/` (ویترین و پلن‌ها)، `/download` (برنامه‌ها) و
`/panel` (کانفیگ‌های من). همه server-rendered هستند؛ هیچ build step و bundle‌ای
نیست که کهنه شود. قیمت‌ها از جدول `plans` و لینک پشتیبانی از `settings` خوانده
می‌شود، پس تغییر در پنل ادمین بلافاصله روی سایت می‌نشیند.

### فایل نصب اختصاصی نساختیم، و این عمدی است

خواست «فایل فیلترشکن با فرمت exe و apk» بود. نساختیم، چون ساختنش در این محیط
ممکن نیست و **جعل کردنش خطرناک است**:

- کلاینت VPN یک باینری native است. روی ویندوز باید درایور TUN/Wintun نصب کند و
  به‌صورت service اجرا شود؛ روی اندروید باید `VpnService` را bind کند و با کلید
  release امضا شده باشد.
- ساخت این‌ها toolchain واقعی می‌خواهد: MSVC یا MinGW برای exe، و Android SDK +
  Gradle + keystore برای apk. در این سندباکس هیچ‌کدام نصب نیستند — تأییدشده با
  `command -v` برای `go`, `rustc`, `cargo`, `x86_64-w64-mingw32-gcc`, `gradle`,
  `javac`, `dotnet`, `apktool`, `aapt2`, `zipalign`, `apksigner`.
- مهم‌تر از امکان‌پذیری: **نصب‌کننده‌ی VPN امضانشده یا خودامضا، بدترین چیزی است
  که می‌شود به کسی داد.** یک exe که ادعا می‌کند VPN است و منبعش معلوم نیست، دقیقاً
  همان چیزی است که آنتی‌ویروس‌ها و کاربران محتاط درست رد می‌کنند.

به‌جایش `configbot/src/ui/clients.ts` بیلد **رسمی و متن‌باز** خود پروژه‌ها را
لینک می‌دهد: Hiddify، v2rayNG و v2rayN. نام هر asset مستقیماً از GitHub API
گرفته شده و هر URL با HEAD چک شده — یک نام asset deliberately غلط `404` می‌دهد،
پس `302`هایی که می‌بینیم واقعی‌اند. نسخه‌ها: Hiddify `v4.1.1`، v2rayNG `2.2.6`،
v2rayN `7.24.9`. برای به‌روزرسانی، همان `curl` که سرِ فایل نوشته شده.

### iOS

`.ipa` برای کسی که developer certificate یا jailbreak ندارد بی‌فایده است، و
هیچ URL‌ی App Store از این محیط قابل تأیید نبود (`http=000`). پس لینک چاپ
نکردیم؛ به‌جایش گفته‌ایم در App Store چه چیزی را جستجو کنند.

### خرید از وب بدون تلگرام

`/pub/api/*` همان جریان خرید است بدون `initData`:

- **اعتبار = توکن اشتراک.** این میان‌بُر جدیدی نیست؛ `/s/<token>` از اول با
  همان توکن کانفیگ می‌داد. پس این endpoint چیزی را لو نمی‌دهد که لینک اشتراک
  نمی‌داد.
- **کوکی سفارش با امضا.** وقتی سفارش ثبت می‌شود، `pub_order=<id>.<sig>` صادر
  می‌شود تا مرحله‌ی فیش بداند سفارش مال کیست. بدون secret قابل جعل نیست.
- **هیچ‌جا خودش سفارش را paid نمی‌کند.** پرداخت از همان
  `submitReceipt` → غربالگری → صف ادمین می‌رود. فیش بدون عکس **reject** می‌شود،
  نه «بعداً بررسی می‌شود».
- **سقف سفارش باز:** بیش از ۵ سفارشِ `pending`/`awaiting_payment` روی یک حساب،
  سفارش جدید رد می‌شود (`429`).

### دو چیز که اگر نباشند، سایت دروغ نمی‌گوید

- **کارت تنظیم نشده** → کارت‌پلن‌ها به‌جای فرم خرید، به ربات لینک می‌دهند.
  فرمی که نتواند پول بگیرد نمی‌گذاریم.
- **R2 وصل نیست** → آپلود فیش با `503` و پیام روشن رد می‌شود، نه اینکه فایل را
  بگیرد و دور بیندازد.

## ۶. کارهایی که عمداً انجام نشد

- **فروش کانفیگ «رایگان نامحدود».** یا از کار افتاده یا مال دیگری است.
- **دور زدن محدودیت TCP/UDP.** با WebSocket یا پروکسی، وانمود کردن به اینکه
  VPN روی ورکر کار می‌کند. کار نمی‌کند و گفتنش دروغ است.
- **استفاده از توکن رباتی که در چت paste شد.** آن توکن لو رفته و باید در
  BotFather باطل شود. هیچ‌جا ذخیره یا استفاده نشد.
- **دکمه‌ی مرده در پنل ادمین.** هر کنترلی که وجود دارد به یک endpoint واقعی
  وصل است؛ اگر قابلیتی نباشد، کنترل هم رندر نمی‌شود.

## ۷. ترتیب راه‌اندازی واقعی

1. **D1:** `npx wrangler d1 create configbot-db` و `database_id` را در
   `configbot/wrangler.toml` بگذار.
2. **اسکима:** `npx wrangler d1 execute configbot-db --remote --file=configbot/src/db/schema.sql`
3. **Secrets:**
   ```
   npx wrangler secret put BOT_TOKEN
   npx wrangler secret put WEBHOOK_SECRET
   ```
4. **دپلوی:** `npx wrangler deploy` → یک `*.workers.dev` می‌گیری.
5. **Webhook:** آن URL را به‌عنوان base به ربات بده؛ `PUBLIC_URL` را هم در
   `[vars]` بگذار.
6. **VPS + Marzban** را راه بینداز و در پنل ادمین → نودها اضافه‌اش کن.
7. **کارت** را در پنل ادمین → تنظیمات وارد کن.

تا مرحله‌ی ۶ ربات بالا می‌آید، پلن می‌فروشد و سفارش ثبت می‌کند — ولی کانفیگ
واقعی صادر نمی‌کند، چون سروری پشتش نیست.
